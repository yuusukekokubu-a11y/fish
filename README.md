# fish

## 概要

スマホのブラウザで動く、タップ主体の「釣り×ハクスラ」(ガチャで集めた装備で強くなるゲーム)です。
目標の姿は「掛かった瞬間の合わせと、強い魚との体力制の駆け引き、ガチャで集めた装備(スキルの組み合わせ)で強くなっていく、長く遊べる釣りゲーム。ガチャのドキドキが核」です。

今できること:

- 投げる → 待つ は自動です。魚が掛かると「!」が出て、浮きに向かって白い輪が縮みます。輪が緑の帯に重なったときにタップして「合わせ」ます。真ん中の金の帯なら「ジャスト!」。早すぎても遅すぎても逃げられます(何もしなければ釣果は増えません)。
- 魚は 3 区分です。弱い魚は、合わせれば釣れます。強い魚は、合わせたあとミニゲームになります(ジャストなら最初の一撃が 1.5 倍)。ゲージの緑の中でタップするたびに魚の体力が減り(「-10」)、ゼロで釣り上げです。ときどきクリティカル(「CRITICAL!」)が出て、2 倍削れます。外すと体力が回復し(「+10」)、時間切れで逃げられます。
- 合わせを 5 回続けて逃すと休みになります。画面をタップすると再開します。
- 釣った魚から「ウロコイン」(ゲーム内のお金)が手に入ります。強い魚からは、その魚の「鱗」も 1 枚手に入ります。
- 竿は「製作 → ヌシ戦 → 進化」で進みます(段階 1〜5)。強い魚の鱗を集めて竿を製作し、下のボタンで「ヌシに挑む」と、その段階の大物「ヌシ」と合わせなしで戦えます(負けても何も減りません)。勝って手に入るヌシの鱗で竿を進化させると、次の段階の新しい魚が釣れます。魚は全部で 15 種類(ヌシ 5 種類を含む)です。
- 大きな数は「1.2万」「3.4億」のように短く出ます。
- ウロコイン・鱗・竿の段階と工程は、ブラウザの中に保存されます(前の版の保存も読めます。前の素材はウロコインに換わります)。消すときは、右上の ☰ で開く目次の「設定」で「データを消す」を 2 回続けて押します。
- 画面の右下に、バージョン(例:`v0.14.0・abc1234`)が出ます。公開に新しい機能が入ったかを確かめられます。手元の `npm start` では `dev` と出ます。
- ☰ の目次の「クレート」で、ウロコインを使って装備のガチャを引けます(1 回か 10 連)。「装備」で糸・リール・ルアーを付けると、強い魚との戦いが楽になります(糸=制限時間、リール=ダメージ、ルアー=命中範囲の広さ)。いらない装備は分解すると、ウロコインが少し戻ります。レア以上の装備にはスキル(強打 Lv2・連撃・攻 Lv1 など)が付き、付けている装備のレベルの合計がスキルのレベルになります。連撃・先手などの条件発動型は、戦いの流れの条件を満たしたときに効きます。芯・縁は、ゲージの命中範囲の真ん中(芯)か端のぎりぎり(縁)で命中したときに効きます。目次の「スキル」で、今のレベルと効果を見られます。
- 右上の ☰ で目次が開きます。装備・スキル・クレート・素材・ステータス・設定の画面に全画面で移れます(開いている間は釣りが止まります)。上の「←」か、スマホの「戻る」で戻れます。目次もスマホの「戻る」で閉じます。
- 目次の「設定」の「セーブコード」で、記録を 1 行の文字列(`FISH7-…`。前の `FISH2-…`〜`FISH6-…` も読めます)に書き出せます。別のブラウザやスマホで「読み込み」に貼り付けると、続きから遊べます。

- 言語:JavaScript(ES modules)。ビルドの道具は使いません。npm の外部の部品は、開発用の型チェックの道具 `typescript` の 1 つだけです(遊ぶ画面とテストは使いません)。
- 必要なもの:Node.js 22 以上(配信とテストに使う)。
- ライセンス:MIT(`LICENSE`)

## 動かし方

### スマホで遊ぶ(公開の URL)

main に取り込まれた内容は、GitHub Pages(GitHub の無料の公開の仕組み)で公開されます。スマホのブラウザで次の URL を開きます。

```
https://yuusukekokubu-a11y.github.io/fish/
```

- 形は `https://(GitHub のユーザー名).github.io/(リポジトリ名)/` です。
- 公開には、オーナーが一度だけ設定をする必要があります(Settings → Pages の「Source」を「GitHub Actions」にする)。設定の前は、公開の手順は飛ばされます。
- シードを固定するときは `https://yuusukekokubu-a11y.github.io/fish/?debug&seed=1` のように付けます(`?debug` のときだけ効きます。デバッグ用のデータで遊ぶので、本番のデータには影響しません)。

### PC で試す

```
npm start
```

表示された `http://localhost:8000/` をブラウザで開きます。スマホ相当の画面で見るには、ブラウザの開発者ツール(F12)で画面幅を 390px 前後にします。止めるときは Ctrl+C を押します。

### スマホで試す(公開の前の変更を、同じ Wi-Fi で)

1. PC とスマホを同じ Wi-Fi につなぎます。
2. PC で `npm start` を実行します。
3. 「同じ Wi-Fi のスマホで開く:`http://192.168.x.x:8000/`」と表示された URL を、スマホのブラウザで開きます。
4. 開けないときは、PC の防火壁(firewall:外からの接続を止める仕組み)が Node.js の接続を止めていないか確かめます。

### シードを固定する

URL の末尾に `?debug&seed=123` を付けると、乱数が固定されます(例:`http://localhost:8000/?debug&seed=123`)。同じシードなら、同じ魚が同じ順で掛かります。付けないときは、画面の右下に今のシードが表示されます。`?seed=` は `?debug` のときだけ効きます(D-215)。

### デバッグ画面

URL に `?debug` を付けると、目次の最後に「デバッグ」が出て、画面の下に「DEBUG」の印が出ます(D-214)。

- デバッグ専用の保存場所を使います。本番のデータは読みも書きもしません。`?debug` を外して開けば、本番のデータに戻ります。
- ウロコイン・鱗・竿を決める、装備を作る、プリセット(よく試す装備の組み合わせ)を装着する、強い魚やヌシとすぐ戦う、クリティカルの確率とシードを決める、デバッグのデータを消す、ができます。
- 確認用の仕組みの全部は SPEC の 5.11 にあります。

## テストの回し方

| やりたいこと | コマンド |
| --- | --- |
| 速いテスト(既定) | `npm test` |
| 特定のテストだけ | `node --test tests/fishing.test.js` |
| 重いテスト | `npm run test:slow` |
| 型チェック(初回だけ先に `npm install`) | `npm run typecheck` |

- `npm test` は速いテスト(`tests/*.test.js`)だけを、ファイルごとに並列で回します。
- 重いテストは `tests/slow/` に `*.test.js` として置きます。0 件でも成功として終わります。
- GitHub では次のように回ります(設定は `.github/workflows/ci.yml`)。
  - PR:速いテストと型チェック。計算本体(`src/core/`)が変わったときだけ重いテストも。
  - main への取り込み後:速いテストと型チェック。
  - 手動:Actions の画面で「ci」を選び「Run workflow」を押すと、重いテストが回ります。
- 公開は別の設定(`.github/workflows/pages.yml`)で、main への取り込みのあとに動きます。
