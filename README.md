# fish

## 概要

スマホのブラウザで動く、タップ主体の釣り×ローグライク/ハクスラ(ランごとに変わる装備で強くなるゲーム)のゲームです。
目標の姿は「掛かった瞬間の合わせと、強い魚との駆け引き(体力制のミニゲーム)、ランごとに変わる装備の組み合わせで強くなっていく、タップ主体の釣りゲーム」です。

今できること:

- 投げる → 待つ は自動です。魚が掛かると「!」が出るので、すぐにタップして「合わせ」ます。間に合わないと逃げられます(何もしなければ釣果は増えません)。
- 普通の魚は、合わせれば釣れます。強い魚は、合わせたあとミニゲームになります。ゲージの緑の中でタップするたびに魚の体力が減り、ゼロで釣り上げです。外すと体力が回復し、時間切れで逃げられます。
- 合わせを 5 回続けて逃すと休みになります。画面をタップすると再開します。
- 釣った魚から「ウロコイン」(ゲーム内のお金)と「素材」が手に入ります。
- 素材で竿を強化すると(段階 1〜5)、新しい魚が釣れるようになります。魚は全部で 10 種類です。
- ウロコイン・素材・竿の段階は、ブラウザの中に保存されます。消すときは、左下の「データを消す」を 2 回続けて押します。
- 下の「セーブコード」で、記録を 1 行の文字列(`FISH2-…`)に書き出せます。別のブラウザやスマホで「読み込み」に貼り付けると、続きから遊べます。

- 言語:JavaScript(ES modules)。ビルドの道具も、npm の外部の部品も使いません。
- 必要なもの:Node.js 22 以上(配信とテストに使う)。
- ライセンス:MIT(`LICENSE`)

## 動かし方

### スマホで遊ぶ(公開の URL)

main に取り込まれた内容は、GitHub Pages(GitHub の無料の公開の仕組み)で公開されます。スマホのブラウザで次の URL を開きます。

```
https://yuusukekokubu-a11y.github.io/fish/
```

- 形は `https://(GitHub のユーザー名).github.io/(リポジトリ名)/` です。
- 公開には、オーナーが一度だけ設定をする必要があります(Settings → Pages の「Source」を「GitHub Actions」にする)。設定の前は、公開の手順は飛ばされます。
- シードを固定するときは `https://yuusukekokubu-a11y.github.io/fish/?seed=1` のように付けます。

### PC で試す

```
npm start
```

表示された `http://localhost:8000/` をブラウザで開きます。スマホ相当の画面で見るには、ブラウザの開発者ツール(F12)で画面幅を 390px 前後にします。止めるときは Ctrl+C を押します。

### スマホで試す(公開の前の変更を、同じ Wi-Fi で)

1. PC とスマホを同じ Wi-Fi につなぎます。
2. PC で `npm start` を実行します。
3. 「同じ Wi-Fi のスマホで開く:`http://192.168.x.x:8000/`」と表示された URL を、スマホのブラウザで開きます。
4. 開けないときは、PC の防火壁(firewall:外からの接続を止める仕組み)が Node.js の接続を止めていないか確かめます。

### シードを固定する

URL の末尾に `?seed=123` を付けると、乱数が固定されます(例:`http://localhost:8000/?seed=123`)。同じシードなら、同じ魚が同じ順で掛かります。付けないときは、画面の左下に今のシードが表示されます。

## テストの回し方

| やりたいこと | コマンド |
| --- | --- |
| 速いテスト(既定) | `npm test` |
| 特定のテストだけ | `node --test tests/fishing.test.js` |
| 重いテスト | `npm run test:slow` |

- `npm test` は速いテスト(`tests/*.test.js`)だけを、ファイルごとに並列で回します。
- 重いテストは `tests/slow/` に `*.test.js` として置きます。0 件でも成功として終わります。
- GitHub では次のように回ります(設定は `.github/workflows/ci.yml`)。
  - PR:速いテスト。計算本体(`src/core/`)が変わったときだけ重いテストも。
  - main への取り込み後:速いテストだけ。
  - 手動:Actions の画面で「ci」を選び「Run workflow」を押すと、重いテストが回ります。
- 公開は別の設定(`.github/workflows/pages.yml`)で、main への取り込みのあとに動きます。
