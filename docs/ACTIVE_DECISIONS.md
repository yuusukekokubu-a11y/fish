# 今有効な決定の一覧(ACTIVE_DECISIONS)

[DECISIONS.md](DECISIONS.md) の決定のうち、今も有効なものだけを分野ごとにまとめた一覧です。
作業の始めに、まずこの一覧を読みます。くわしい理由が必要なときだけ、元の D 番号を DECISIONS で読みます。
決定を足す・変えるたびに、この一覧も直します。DECISIONS の D 番号は、必ずこの一覧か末尾の「載せなかった決定」のどちらかに出します(テストで確かめています)。

## 書式の見本

```
## 分野の名前

- 決定の要点を 1〜2 行で。(D-XXX)
```

---

## 進め方

- オーナー(意思決定と感想)・壁打ちの Claude(設計・依頼文・レビュー)・Code(実装)の 3 者で進める。依頼は 1 つずつ、1 依頼で 1 PR。(D-001)
- 依頼の【0】の決定は作業の最初に記録する。実装中の細部は Code が決めて報告する。(D-004)

## 記録と報告

- 取り込みごとに報告 Issue を 1 つ発行する。識別子は Issue 番号だけで、別の報告は番号で指す。(D-002)
- 決定は DECISIONS に D 番号で残し、有効なものをこの一覧にまとめる。リポジトリが正本。(D-003)

## テストと取り込み

- 手元は速いテストと関係するテストだけ。全体は GitHub の PR で 1 回。重いテストは計算本体が変わった PR だけ自動。GitHub のテストが通ってから取り込む。(D-005)
- 計算本体は `src/fish/`。ここか `tests/slow/` などが変わった PR だけ重いテストを回し、判定は `scripts/ci_needs_slow.py`。(D-012)
- 重いテストは marker「slow」で印を付ける。`pytest` だけなら速いテストのみ、重いテストは `python scripts/run_slow_tests.py`。(D-013)
- 外部の部品(Action)は `actions/checkout` と `actions/setup-python` だけで、commit の番号で固定する。(D-014)
- 取り込みの可否は `ci-result` ジョブ 1 つで判断する。(D-015)

## 文章とファイル

- ファイルは 800 行以内が目安。超えるなら分けるか、理由を DESIGN に書く。(D-006)
- 平易な日本語で書き、専門用語に短い説明を付ける。英語は単語だけ。(D-007)

## データの扱い

- 実在のデータや秘密の情報をリポジトリに入れない。例やテストは作り物のデータを使う。(D-008)

## 技術の選択

- Python 3.12 と pytest。確かめる版は 1 つ。(D-009)
- ライセンスは MIT。(D-010)
