## 目的と方針

- スマホのブラウザで動く、釣り×クリッカー×ローグライク/ハクスラのゲームを作る。(D-016)
- 目標の姿「自動で釣れる気持ちよさと、強い魚とのミニゲーム、ランごとに変わる装備の組み合わせで強くなっていく釣りゲーム」を、迷ったときの判断の基準にする。(D-017)
- 作る順番:①釣りの 1 サイクル → ②釣ったものと素材 → ③強化 → ④ローグライク・ハクスラ要素。(D-023)

## ゲームの決まり

- 普通の魚は自動で釣れ続ける。強い魚はミニゲーム。強い魚ほど重いミニゲームにする。(D-018)
- 1 ランは数分の時間制。時間が尽きたら終わり、持ち帰った素材で強化する。(D-019)
- 乱数はシードで固定できる。同じシードなら同じ結果。(D-021)
- 待ち時間 1.5〜7.5 秒、強い魚 20%、印は 0.9 秒で端から端、当たり範囲 22%、5 秒で逃げる。数値は `src/core/config.js`。(D-029)

## 画面と動作環境

- 縦持ちのスマホ向け。動作環境はスマホのブラウザ。(D-020)
- シードは URL の `?seed=123` で指定できる。手元とスマホでは `npm start` で配信して試す。(D-030)

## 進め方

- オーナー(意思決定と感想)・壁打ちの Claude(設計・依頼文・レビュー)・Code(実装)の 3 者で進める。依頼は 1 つずつ、1 依頼で 1 PR。(D-001)
- 依頼の【0】の決定は作業の最初に記録する。実装中の細部は Code が決めて報告する。(D-004)
- main の保護(`ci-result` の成功を必須にする設定)は、オーナーが行う。(D-024)

## 記録と報告

- 取り込みごとに報告 Issue を 1 つ発行する。識別子は Issue 番号だけで、別の報告は番号で指す。(D-002)
- 決定は DECISIONS に D 番号で残し、有効なものをこの一覧にまとめる。リポジトリが正本。(D-003)

## テストと取り込み

- 手元は速いテストと関係するテストだけ。全体は GitHub の PR で 1 回。重いテストは計算本体が変わった PR だけ自動。GitHub のテストが通ってから取り込む。(D-005)
- 計算本体は `src/core/`、画面は `src/ui/`。`src/core/` や `tests/slow/` などが変わった PR だけ重いテストを回し、判定は `scripts/ci_needs_slow.mjs`。(D-028)
- 速いテストは `npm test`(並列)。重いテストは `tests/slow/` に置き `npm run test:slow`(0 件でも成功)。(D-026)
- 外部の部品(Action)は `actions/checkout` と `actions/setup-node` だけで、commit の番号で固定する。(D-027)
- 取り込みの可否は `ci-result` ジョブ 1 つで判断する。(D-015)

## 文章とファイル

- ファイルは 800 行以内が目安。超えるなら分けるか、理由を DESIGN に書く。(D-006)
- 平易な日本語で書き、専門用語に短い説明を付ける。英語は単語だけ。(D-007)

## データの扱い

- 実在のデータや秘密の情報をリポジトリに入れない。例やテストは作り物のデータを使う。(D-008)

## 技術の選択

- 素の JavaScript(ES modules)で、ビルドなし・npm の外部の部品なし。テストは Node.js 22 の `node --test`。(D-025)
- ライセンスは MIT。(D-010)
