## 目的と方針

- 用語:命中(命中範囲の中のタップでダメージ)、ミス(外のタップで回復)、命中範囲、合わせ(成功・ジャスト・失敗。「命中」は使わない)、高レア・低レア(「当たり外れ」は使わない)。SPEC に用語集。(D-180)

- スマホのブラウザで動く、タップ主体の「釣り×ハクスラ」。放置で進む作りにはしない(操作がないと釣果は増えない)。時間制のランとローグライクはなくす。(D-119)
- 目標の姿「掛かった瞬間の合わせと、強い魚との体力制の駆け引き、ガチャで集めた装備(スキルの組み合わせ)で強くなっていく、長く遊べる釣りゲーム。ガチャのドキドキが核」を、迷ったときの判断の基準にする。(D-119)
- 作る順番:②-4b4 デバッグ画面・満タンの警告・スキル画面のグループ分け・記録の直し → ②-4c 防御と貫通・連撃・貫・魚側の強化・魚の入れ替え・互換性を切る(分割する案あり)→ ②-4d 釣り場 → ②-5(おもり・浮き・おまもり、グローブ、釣れるクレート、大物狙い)→ ③強化の拡張 → デザインのテコ入れ。(D-218)
- デバッグ画面は `?debug` のときだけ。本番とは別の保存場所。公開用のファイルに含める(サーバーがなく、影響は使った人のブラウザだけ)。ランキング・オンライン・課金を入れるときに外す。(D-214)
- 確認用の仕組み(URL の指定・window の関数)は SPEC に一覧。コードが読む URL の指定は一覧のものだけ。(D-215)
- 持ち物が満タンのときは引けないまま、警告を分かりやすくする(装備が黙って消えない)。(D-216)
- スキルの画面は 数値型・条件発動型・ゲージ系 の 3 グループ(表で持つ)。(D-217)
- 長期コンテンツは釣り場で区切る(釣り場ごとに魚 10・ヌシ 5、竿は釣り場ごとに段階 1 から、クレートは釣り場ごと、数値は「基準の強さ × 段階」の式。並びの案は 港 → 磯 → 川 → 沖 → 外洋 → 深海)。(D-201)
- ②-4c:マグロは外洋の最後へ、港は小さな魚で完結(カツオは沖へ)。互換性は ②-4c で 1 回だけ切る。段階 100・魚 300 種類の表で壊れないことを確かめる。ヌシ戦は魚側の体力と防御で強める。(D-202・D-203・D-204・D-205)
- ②-4b の範囲:成長型 6 個(会心率・会心威力・強打・粘り・豊漁・目利き)、頭打ち型 4 個(俊敏・見極め・名人技・回復の軽減、最大 Lv3)、追加クリティカル、セーブコードの短縮(配列・版 5)。ルアーの外し得がないことをシミュレーションで確かめる。(D-157)

## 経済と進行度

- 魚からウロコインと鱗が手に入る。鱗は魚ごとに別で、強い魚とヌシだけが落とす。鱗は竿の製作と進化、ウロコインはクレートガチャ(②-4)に使う。(D-097)
- 竿の製作は通過点(関門にしない)。関門はヌシ戦と、ヌシの竿への進化。(D-212)
- 竿は「鱗を貯める → 製作 → ヌシ戦 → 進化」で段階ごとに進む。製作と進化は確実、ヌシ戦は腕前。竿は進行度の軸で、強さの効果は持たない。(D-098・D-100)
- 工程は `none`・`crafted`・`defeated`・`evolved`(最後の段階だけ)。製作の鱗はクロダイ 3・スズキ 4・ブリ 4・カツオ 5・マグロ 6、進化はヌシの鱗 1。(D-114)
- 弱い魚は稼ぎ、強い魚は進行の素材。時間あたりの期待報酬は強い魚が上。報酬の数は D-112 の表。(D-095・D-112)
- 詰み防止:弱い魚でウロコインが増え、クレートを引き続けられる道を常に守る。(D-102)
- 装備の入手はガチャだけ。天井や保険はなし。ウロコインだけで引き、排出率を出す。1 回引きと 10 連(演出を飛ばせる)。引く演出が核。(D-120・D-121)
- 分解するとウロコインが少し返る(クレートの価格の 1 割前後、レア度が高いほど多い)。かけらは作らない。10 連は 1 回の 10 倍。(D-137・D-138)
- ガチャはドロワーの「クレート」タブ。演出は画面全体。開いている間は釣りが止まる。持ち物には上限があり、空きが足りないと引く前に止める。(D-139・D-140)
- ガチャの乱数は別系統で、種と引いた回数から作る。種はデータを作ったときに決めて保存(`?seed=` があればそれ)。(D-141)
- ②-4a は糸・リール・ルアーの 3 枠だけ。スキル・防御と貫通は作らない。(D-142)
- 装備は戦闘の数値の表の項目 1 つに効かせる(糸=制限時間、リール=ダメージに足し算、ルアー=命中範囲の幅 +n%)。安全上限だけ。ルアーの上限はゲージの約 70%、下限 10% は変えない。ミスは回復だけ(ミスのボーナスはなし)。外し得なしを重いテストで確かめる。(D-181)
- 価格 = (1 回投げたときの期待値 ÷ 8.6 秒)× 120 秒 を 2 けたに丸める。クロダイ 20 〜 マグロ 630。(D-146)
- 排出率 70%・22%・6.5%・1.5%。範囲 = 基本の範囲 ×(1 + 0.35(グレード − 1))× レア度の倍率(1・1.5・2.2・3.2)。糸 0.5〜1.0 秒(0.1 秒刻み)、リール +1〜+2、ルアー +2〜+4。(D-147)
- ガチャの乱数は種と回数から、1 回につき レア度 → 種類 → 値。種は画面が決めて保存(`?seed=` は決めるときだけ)。(D-148)
- 持ち物は 100 個まで。分解は価格 × 6%・12%・25%・50%(平均 約 9.2%)。まとめて分解は装着中を除く。(D-149)
- 装備の画面:枠は 2 列のグリッド(7 枠でも 4 段)、持ち物は★つきのカード、並べ替えと種類の絞り込み、詳細は下から出るシート、確認もシート。クレートの画面:持ち物の空き、くわしく(排出率と範囲)、引く演出は前のまま(溜め 1.2 秒 → 光 → 結果、タップで飛ばす)、結果に「装備を見る」。▲ は付けている装備より高いとき。(D-162)
- クレートは竿の段階ごとに 1 種類。価格とグレードは段階の数式。価格は「段階の毎秒の稼ぎ × 目標の時間(1〜3 分)」。ガチャの乱数は別系統。(D-122)
- 数は安全な整数の上限で止め、画面では「1.2万」「1.2億」「1.2兆」と短く出す。(D-116)
- 竿は進行度の軸。段階が上がると新しい魚が加わる。待ち時間と強い魚の出やすさは竿では変えない。(D-033)
- 装備は糸・おもり・リール・浮き・ルアー・おまもり。通常のクレートから出る。釣れるクレートはグローブだけ(②-4a・②-5、D-218)。(D-038)
- クレートは現実のお金を使わず、排出率を画面に出す。(D-039)
- グローブの能力に「自動合わせ」をレアで入れる方針(②-5、D-218)。(D-057)
- 装備は生成型(種類 × レア度 × グレード × スキル)。名前は段階の魚から(クロダイの糸)。基本効果 1 つ(ばらつきあり)+スキル 0〜3 種類。レア度 4 段階。同じものは分解して素材。糸=制限時間、リール=ダメージ、ルアー=命中範囲の広さ(D-181)、おもり=待ち時間、浮き=成功帯、おまもり=報酬、グローブ=特殊能力。(D-123)
- スキルは完全にレベル制:装備のスキルは整数のレベル、装着中の装備のレベルの合計がスキルのレベル(最大で止まり、余りは無駄)。装備のレベルはレア度とグレードで決まる。旧装備のポイントは ÷4 を四捨五入(最低 1)。数はレア度で 0〜3、同じ装備に重複なし。タグのシナジー・救済・反骨は外す。(D-195)
- 大物狙い(強い魚の出現率を上げるスキル)は ②-5 で作り、上げ幅に上限を置く(進行のペース:ウロコインの稼ぎと鱗の集まる速さを保つため)。ルール変更型のスキルは将来の控え。(D-213)
- 頭打ち型は 4 つだけ(俊敏・見極め・名人技・回復の軽減、最大 Lv3、余りは無駄)。ほかは成長型で、最大レベルは段階で伸ばす。(D-125)
- 会心率は成長型。100% 超は追加クリティカル(整数部分が段数、小数部分がもう 1 段の確率)。(D-126)
- 数値型スキル 9 個:成長型 強打・会心率・会心威力・粘り・豊漁、頭打ち型(Lv3)俊敏・見極め・名人技・回復の軽減。目利きは廃止(1 匹から鱗は 1 枚しか取れないので、% で上げても意味がない)。豊漁の端数は四捨五入。(D-211)
- ガチャのスキルの抽選は 18 個(数値型 9・条件発動型 7・ゲージ系 2)。(D-198)
- 成長型の最大レベルは竿の段階で伸びる、頭打ち型は Lv3。余りは無駄。(D-167)
- 条件発動型 7 個(全て成長型、最大は「2 + 竿の段階」):連撃・攻、連撃・心、先手、ジャスト・ブースト、とどめ(体力 25% 以下)、勢い、先制。連撃・貫は ②-4c。(D-184)
- 連撃の段数は連続した命中の数。ミスでリセット、戦闘の終わりで消える。連撃のスキルで共有、最大段数は表(目安 10)。(D-185)
- 条件発動型は戦闘中の一時的な上乗せに載せる。止めても保持、戦闘の終わりで消える、保存しない。(D-186)
- ヌシ戦の開始は合わせの成功とみなす(先手は効く、ジャスト・ブーストは効かない)。(D-187)
- ヌシ戦の長さ(最強の装備で何回の命中か)は ②-4c で、ヌシの体力と防御とまとめて調整する。スキルの数値とヌシの体力は今のまま。(D-190)
- ゲージ系スキル:命中範囲を中心からの距離で 芯・通常・縁 に分ける(幅に対する割合。ルアーで広がると帯も広がる)。芯で命中すると会心率 +n%、縁で命中するとダメージ +n%。成長型。命中範囲拡大のスキルは作らない。(D-197)
- 芯は中心からの距離 0.3 以下で会心率 +10%/Lv、縁は 0.75 以上でダメージ +20%/Lv。計算は 基本 ×(1 + とどめ + 縁)→ クリティカル → ジャスト。ゲージの色分けと「芯」「縁」の表示は、スキルを付けたときだけ。(D-209)
- 条件発動型の効果:連撃・攻 +1/段、連撃・心 +3%/段、先手 +4、ジャスト・ブースト +0.15、とどめ +15%、勢い +10%、先制 +10%(1 Lv あたり)、連撃は最大 10 段。計算は 基本(表 + 連撃・攻 + 先手)→ とどめ → クリティカル → ジャスト。戦闘の画面に「連撃 ×n」と条件の名前、ステータスに「条件つき」。(D-191)
- 先制は満タンで、その戦闘の最初の命中まで(満タンに戻す外し得をなくす)。(D-192)
- ルアーは基本 5〜7.5%(レジェンド・グレード 1 で +16〜24%、グレード 5 で +38〜58%)。真ん中を保って広げ、上限 70%・下限 10%。旧ルアーは範囲の中の位置で読み替え。(D-193)
- 用語の点検は、画面に出る文字を集めて古い言い方がないかをテストで確かめる。(D-194)
- 効果(1 Lv):強打 +2・会心率 +15%・会心威力 +0.2・粘り +1 秒・豊漁 +10%(四捨五入)・俊敏 −10%(下限 1 秒)・見極め +0.1 秒・名人技 +0.04 秒・回復の軽減 −1/3。順は 装備 → スキルの足し算 → 掛け算 → 点検。(D-210)
- 保存は版 7・FISH7(スキルがレベルになるため)。FISH6 以前も読める。互換性は ②-4c まで切らない。(D-199)
- 保存は版 6・FISH6(ルアーの意味が変わるため)。旧ルアーはレア度・グレードの範囲の中の相対位置を保って読み替え。条件発動型の番号は表の末尾。(D-188)
- 装備 1 個のレベル:上限 =(段階の最大 ÷ 3)× レア度の倍率(レア 0.7・エピック 1・レジェンド 1.5)、下限はその半分(最低 1)。最良 3 個で最大に届き、平均的な装備では 6〜7 割。ガチャはレア度 → 種類 → 値 → スキル → レベルの順。(D-207)
- 旧装備(版 4 まで)はスキルなしで引き継ぐ。(D-172)
- 版 7 の装備は表の番号とレベルの配列。版 6 までのポイントは ÷4 を四捨五入(最低 1、新しい範囲に収める)、目利きは取り除く。壊れた・範囲外・重複・持ち物にない装着は拒否。コードは 2 万文字まで(100 個で約 5000 文字)。(D-208)
- 新しい画面「スキル」。装備の画面は枠を上に固定。目次を開くと履歴を足し、「戻る」で閉じる。(D-173)
- スキルの画面は Lv/最大・細い棒・効果・MAX の印、装備のカードにスキルの行、付け替えのスキルレベルの差、ステータスに段の内わけと報酬の節、「CRITICAL ×n!」。(D-179)
- 魚の防御(割合型、上限なし、段階 1 は 0%)とスキルの貫通。計算は 通常 → 倍率 → 実効防御 → 最小 1。②-4c。(D-128)
- 装備なしで釣れるのは序盤(段階 1〜2 目安)の強い魚だけでよい。ヌシはいつでも何度でも挑め、負けても減らない。古い魚の鱗の使い道は将来。(D-129・D-108)
- 魚の性質(弱点・暴れ方)と装備の相性は将来の控え。(D-075)
- セーブコードで、ウロコイン・鱗・竿の段階と工程・釣れた魚を書き出し・読み込みできる。サーバーとアカウントは使わない。(D-059)

## 魚

- 魚は種類ごとのデータ(名前・区分・段階・報酬・ミニゲームの重さ)。「レベル」は使わない。(D-034)
- 魚は 3 区分:弱い魚(合わせだけ・鱗なし)、強い魚(合わせ+体力制・自分の鱗・出現率低め)、ヌシ(各段階 1 体・挑戦ボタンで戦う)。(D-094)
- 名前:弱い魚 アジ〜ヒラメ、強い魚 クロダイ〜マグロ、ヌシ・クロダイ〜ヌシ・マグロ(段階 1〜5)。(D-099)
- 設定表は `src/core/fish.js` の魚の表と段階の表。段階の数は表の行の数で決まる。`createGame` に別の表を渡せる。(D-111)
- 表は項目名つき:魚 `{ id, name, kind, stage, coins, scales, color, size, minigame }`(区分は weak・strong・boss)、段階 `{ stage, craft, boss, evolve }`。点検は `checkContent`。(D-136)
- 強い魚の出現率は 10%(`config.strongChance`)。並びの記録は `fish_order.json` に作り直した。(D-096・D-113)
- ヌシ:体力は強い魚の 3.5 倍、制限時間 30〜50 秒。投げる・待つの間だけ挑め、待っていた魚は取っておく。乱数は挑戦回数から。負けても鱗は減らない。今は装備なしで倒せる強さ。(D-115)
- 竿の段階 n では段階 n 以下の魚だけ。新しい魚ほど出やすい。(D-035)
- 段階が上の魚ほど報酬が大きく、ミニゲームが重い。当たり範囲の最小幅と印の速さの上限を決める。(D-036)
- 抽選は 1 回の乱数で区分と種類を決める。重みは段階ごとに 2 倍。(D-046)
- 印の速さと当たり範囲は魚ごと。限界は幅 10%・端から端 0.45 秒。(D-048)

## ゲームの決まり

- 合わせは「縮む輪」。「!」の前のタップは無反応。輪が大きいうちは早すぎ、成功帯で成功、真ん中のジャスト帯でジャスト、通り過ぎたら遅すぎ。早すぎ・遅すぎは逃げる。弱い魚は合わせで釣り上げ、強い魚は合わせのあと体力制のミニゲーム。(D-082)
- 輪の数値:普通 1.6 秒・成功帯 0.6 秒・ジャスト帯 0.2 秒、強い 1.2 秒・0.4 秒・0.14 秒。下限は輪 1.0・成功帯 0.25・ジャスト帯 0.10・早すぎの区間 0.3 秒。待ち時間・5 回で休みは前のまま(強い魚の出現率は D-113 で 10%)。(D-087)
- 判定は「!」からの時間で、始まりを含み終わりを含まない。理由は `early`・`late`。乱数は使わない。(D-088)
- ジャスト:強い魚は最初の当たりが 1.5 倍(上乗せの一覧 `fight.boosts`、外しても持ち越し)。弱い魚は表示だけ。倍率は 1.5 倍のまま。(D-083・D-089・D-103)
- 合わせの数値も戦闘の数値の表(`hook`)に入れる。浮き(②-5)で帯を広げられる。(D-084)
- 強い魚は体力を持ち、当たり範囲のタップで減り、ゼロで釣り上げ。強い魚ほど体力が多い。(D-056)
- 戦闘は数値:体力のバー、ダメージの数字、クリティカル(確率で倍率ぶん増える)、外したときの回復。(D-068)
- 体力はクロダイ 20 …… マグロ 60、制限時間 8〜12 秒。基本の表はダメージ 10・確率 10%・倍率 2・回復 10。四捨五入。確率と倍率は安全上限だけ(段数と総倍率)。会心率 c% は c/100 の商が必ず起きる段数、余りがもう 1 段の確率、ダメージは倍率の段数乗。100% 以下は前と同じ。(D-169)
- クリティカルは確率で出し、装備で確率と倍率を上げられる。判定は規則の一覧で、後から条件を足せる。腕前型は ②-4b3 の「芯」に統合。(D-069・D-080・D-197)
- 戦闘の数値は「戦闘の数値の表」でデータとして持ち、`createGame` に渡す。装備はこれを書き換える。(D-071・D-080)
- クリティカルの乱数はミニゲームの系統の中の専用の小系統から、当たりのたびに 1 回引く。(D-079)
- 乱数はシードで固定できる。同じシードなら同じ結果。(D-021)
- 乱数は「魚の系統」と「ミニゲームの系統」に分ける。待ち時間と魚の並びは操作によらず同じ。(D-064)
- 当たり・外れで画面が反応する演出を入れる。(D-042)

## 画面と動作環境

- 画面の右下にバージョン「v0.10.0・abc1234」。番号は `src/version.js`(依頼ごとに真ん中を上げる)、識別番号は公開の処理が書き込む。手元は `dev`。(D-085・D-091)

- 保存は localStorage の `fish:save` に版 3 の JSON(鱗の表・竿の段階と工程)。古い版は版ごとの関数で読み替え、前の素材はウロコインに換える。表にない鱗は持ち続ける。セーブコードは `FISH3-中身-印`(`FISH2` も読める)。(D-104・D-117)
- 保存は版 4(装備の持ち物・装着・引いた回数・ガチャの種)、セーブコードは `FISH4`。前の版も読める。(D-143)
- 右上の ☰ で右から開くドロワーメニュー(素材・ステータス・設定。装備タブは ②-4a)。一覧と詳細の 2 段構え。開いている間は釣りを止める。未入手の鱗は「?」。(D-130)
- ☰ は釣りの絵の右上。メニューは数の欄の下から幅 85%。止めるのは画面の窓口 `session.js` が時間とタップを渡さないことで、計算本体は変えない。外側は click で閉じる。(D-134)

## 進め方

- オーナー(意思決定と感想)・壁打ちの Claude(設計・依頼文・レビュー)・Code(実装)の 3 者で進める。依頼は 1 つずつ、1 依頼で 1 PR。(D-001)
- 依頼の【0】の決定は作業の最初に記録する。実装中の細部は Code が決めて報告する。(D-004)
- main の保護(`ci-result` の成功を必須にする設定)は、オーナーが設定済み。(D-077)

## 記録と報告

- 取り込みごとに報告 Issue を 1 つ発行する。識別子は Issue 番号だけで、別の報告は番号で指す。(D-002)
- 報告 Issue は PR が取り込まれてから発行し、取り込み後の main のテスト結果も書く。(D-031)
- 決定は DECISIONS に D 番号で残し、有効なものをこの一覧にまとめる。リポジトリが正本。(D-003)

## テストと取り込み

- 手元は速いテストと関係するテストだけ。全体は GitHub の PR で 1 回。重いテストは計算本体が変わった PR だけ自動。GitHub のテストが通ってから取り込む。(D-005)
- 計算本体は `src/core/`、画面は `src/ui/`。`src/core/` や `tests/slow/` などが変わった PR だけ重いテストを回し、判定は `scripts/ci_needs_slow.mjs`。(D-028)
- 速いテストは `npm test`(並列)。重いテストは `tests/slow/` に置き `npm run test:slow`(0 件でも成功)。(D-026)
- 外部の部品(Action)は `actions/checkout`・`actions/setup-node`・`actions/upload-pages-artifact`・`actions/deploy-pages` の 4 つで、commit の番号で固定する。公開は `pages.yml`、Pages の設定前は飛ばす。(D-052)
- 取り込みの可否は `ci-result` ジョブ 1 つで判断する。(D-015)

## 技術の選択

- 言語はブラウザ用の JavaScript 系。(D-022)
- 素の JavaScript(ES modules)で、ビルドなし。テストは Node.js 22 の `node --test`。npm の外部の部品は、開発用の型チェックの道具 `typescript` の 1 つだけ(版を固定)。新しいファイルは JSDoc で型を書き、`tsc --noEmit` を CI で回す。既存のファイルは今回は直さない。(D-144)
- TypeScript には移らない。新しいファイルは JSDoc、既存は触るときに足す。(D-158)
- `typescript` は 5.9.3 に固定。`tsconfig.json` の `files` に `// @ts-check` のファイルを並べる。CI の「型チェック」ジョブで `npm ci` → `npm run typecheck`。(D-150)
- ライセンスは MIT。(D-010)
