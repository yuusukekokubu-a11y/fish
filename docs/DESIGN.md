## どこに何を書くか

| 置き場所 | 中身 |
| --- | --- |

| `src/core/config.js` | ゲームの数値(D-029)。手触りの調整はここを直す。 |

| `src/core/minigame.js` | ミニゲームの印の動きと判定。 |

| `src/ui/` | 画面の表示と操作。`main.js` が時間を進めてタップを受け取り、`draw.js` が絵を描く。 |
| `tests/*.test.js` | 速いテスト。`npm test` で並列に回る。 |
| `tests/slow/*.test.js` | 重いテスト(D-026)。`npm run test:slow` で回る。 |
| `tests/helpers.js` | テストで共通に使う道具(テストではない)。 |
| `scripts/` | 開発用の小さなスクリプト(配信、GitHub のテストの判定、重いテストの実行)。 |
| `.github/workflows/` | GitHub のテストの設定。 |
| `.github/ISSUE_TEMPLATE/` | 報告 Issue のひな形。 |
| `docs/` | 決定・仕様・設計・予定・要望の文書(README の「docs の地図」を参照)。 |
| `CLAUDE.md` | Code の作業手順書。 |

### 計算本体と画面の分け方

- 計算本体は「状態」と、それを変える関数(`update` で時間を進める、`tap` でタップする)だけを持つ。時計や画面には触らない。
- 画面(`src/ui/main.js`)は、ブラウザの描画のたびに経過時間を `update` に渡し、状態を読んで描く。
- こうすると、テストでは時間を好きなだけ早送りでき、同じシードで同じ結果になることを確かめられる。

### ファイルの大きさの目安

- 1 つのファイルは 800 行以内を目安にする。超えるなら分ける(D-006)。
- 分けない場合は、下の「800 行を超えるファイル」にファイル名と理由を書く。`tests/file_size.test.js` が、ここに載っていない 800 行超えのファイルを見つけると失敗する。

## GitHub のテストの流れ

設定は `.github/workflows/ci.yml` の 1 つです。

| いつ | 回るもの |
| --- | --- |
| PR を出した・更新したとき | 速いテスト。計算本体(`src/core/`)などが変わったときだけ重いテストも(D-005・D-028)。 |
| main に取り込んだあと | 速いテストだけ(版は 1 つ)。 |
| 手動(Actions の画面の「Run workflow」) | 重いテスト。 |

- 同じ PR を出し直したときは、古い実行を止める(concurrency:同時に走る実行のまとめ役の設定)。
- 最後の `ci-result` ジョブが、ほかの結果をまとめる(D-015)。
- 速いテストは `node --test` がファイルごとに並列で回す。外部の部品がないので `npm install` の待ちもない。

## 検討中の論点

### TypeScript に移るか

- 状況:今は素の JavaScript(D-025)。型の安全はないが、ビルドなしでブラウザがそのまま読める。
- 案:A 案:このまま。必要なら JSDoc(コメントで型を書く方法)を足す/B 案:コードが大きくなったら TypeScript とビルドの道具(esbuild など)を入れる。
- 決める時期:④ローグライク・ハクスラ要素の前(装備の組み合わせでデータの形が複雑になるため)。

### ミニゲームの手触り

- 状況:印の速さ(端から端 0.9 秒)・当たり範囲の幅(22%)・時間切れ(5 秒)は仮の値(D-029)。
- 案:オーナーに試してもらい、「簡単すぎ/難しすぎ」で `src/core/config.js` を直す。強い魚ほど重くする(D-018)ときは、魚ごとに速さと幅を変える。
- 決める時期:②釣ったものと素材の依頼まで。

### スマホで試す方法

- 状況:今は同じ Wi-Fi の PC から配信して試す(D-030)。外からは開けない。
- 案:A 案:このまま/B 案:GitHub Pages(GitHub の無料の公開の仕組み)で公開する。公開の設定はオーナーが決める。
- 決める時期:オーナーの都合しだい。
