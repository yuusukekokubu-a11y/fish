### 計算本体と画面の分け方

- 計算本体は「状態」と、それを変える関数(`update` で時間を進める、`tap` でタップする)だけを持つ。時計や画面には触らない。
- 画面(`src/ui/main.js`)は、ブラウザの描画のたびに経過時間を `update` に渡し、状態を読んで描く。
- こうすると、テストでは時間を好きなだけ早送りでき、同じシードで同じ結果になることを確かめられる。
- 演出(`src/ui/effects.js`)は、計算本体の結果(`game.results`)を読むだけで、書き換えない(D-051)。
- 進み具合(ウロコイン・素材・竿の段階・釣れた魚)は `game.progress` にまとめ、保存はこれだけを対象にする。

### 魚の抽選のしくみ(D-046)

1 回の投げで引く乱数は 3 つ(強い魚でなければ 2 つ)で、順番は変えない。

1. 待ち時間:`1.5 秒 + 乱数 × 6 秒`
2. 魚:乱数 u が 0.2 未満なら強い魚、それ以外は普通の魚。区分の中での位置(強い魚なら u ÷ 0.2)を 0〜1 に引きのばし、その値で重みづけで種類を選ぶ。
3. 当たり範囲の位置(強い魚だけ)

段階 1 では、区分ごとに魚が 1 種類しかないので、乱数の使い方は Issue #4 のときと全く同じになる。


### ファイルの大きさの目安

- 1 つのファイルは 800 行以内を目安にする。超えるなら分ける(D-006)。
- 分けない場合は、下の「800 行を超えるファイル」にファイル名と理由を書く。`tests/file_size.test.js` が、ここに載っていない 800 行超えのファイルを見つけると失敗する。

## GitHub のテストの流れ

設定は `.github/workflows/ci.yml` の 1 つです。

| いつ | 回るもの |
| --- | --- |
| PR を出した・更新したとき | 速いテスト。計算本体(`src/core/`)などが変わったときだけ重いテストも(D-005・D-028)。 |
| main に取り込んだあと | 速いテストだけ(版は 1 つ)。 |
| 手動(Actions の画面の「Run workflow」) | 重いテスト。 |

公開は `.github/workflows/pages.yml` で、テストとは別に動きます(D-052)。

| いつ | 動くもの |
| --- | --- |
| main に取り込んだあと | `index.html` と `src/` を GitHub Pages に公開する。 |
| 手動(Actions の画面で「pages」を選び「Run workflow」) | 同じく公開する。 |

- Pages の設定(Settings → Pages の Source を「GitHub Actions」)が済む前は、公開の手順を飛ばして成功で終わる。

- 同じ PR を出し直したときは、古い実行を止める(concurrency:同時に走る実行のまとめ役の設定)。
- 最後の `ci-result` ジョブが、ほかの結果をまとめる(D-015)。
- 速いテストは `node --test` がファイルごとに並列で回す。外部の部品がないので `npm install` の待ちもない。

## 検討中の論点

### TypeScript に移るか

- 状況:今は素の JavaScript(D-025)。④の前に決める(D-044)。
- 案:A 案:このまま。必要なら JSDoc(コメントで型を書く方法)を足す/B 案:TypeScript とビルドの道具(esbuild など)を入れる。
- 決める時期:④ローグライク・ハクスラ要素の前。

### ミニゲームと手応えの調整

- 状況:印の速さ・当たり範囲の幅は魚ごとの仮の値(D-045・D-048)。演出の強さ(光る時間、揺れの幅)も仮の値(D-051)。
- 案:オーナーに試してもらい、`src/core/fish.js`(魚ごとの重さ)と `src/ui/effects.js`(演出)を直す。
- 決める時期:②-2 の依頼まで。

### 強化のカーブと報酬の釣り合い

- 状況:強化の素材(10・30・80・200)と魚の報酬は仮の値(D-045・D-047)。ウロコインはまだ使い道がない(②-2 で使う)。
- 案:オーナーが遊んだ感想で直す。②-2 でクレートの値段を決めるときに、ウロコインの増え方と合わせて見直す。
- 決める時期:②-2 の依頼まで。
